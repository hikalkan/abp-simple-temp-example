# AbpTempSimpleApp — agent rules

ABP **single-layer** MVC app (.NET 10, SQLite, LeptonX). One project: `AbpTempSimpleApp/`. Detailed Cursor rules live in `.cursor/rules/`; this file is the short version OpenCode reads at runtime.

## Layout

```
AbpTempSimpleApp/
├── Data/              AbpTempSimpleAppDbContext, migrations helpers
├── Entities/{Feature}/
├── Services/{Feature}/  app services + I*AppService
├── Services/Dtos/{Feature}/
├── ObjectMapping/       Mapperly mappers (MapperBase<,>)
├── Pages/{Feature}/     Razor Pages UI
├── Permissions/
├── Localization/
└── Migrations/          generated by EF CLI only
```

New features: group by feature folder (entity, DTOs, service, pages together). Follow the existing **Books** sample.

## EF Core migrations (critical)

- **Never** create or edit files under `Migrations/` by hand.
- After changing entities or `AbpTempSimpleAppDbContext`, run from repo root:

```bash
cd AbpTempSimpleApp
dotnet ef migrations add Added_YourFeature
```

- Apply locally: `dotnet ef database update`  
  In Taskever preview, `taskever.yaml` init runs `--migrate-database` once before preview — do not duplicate that in feature work unless asked.
- Always call `b.ConfigureByConvention()` on new entities in `OnModelCreating`.
- Use table prefix `App` (`AbpTempSimpleAppDbContext.DbTablePrefix`).
- Data access goes through `IRepository<T, Guid>` — **never** inject `AbpTempSimpleAppDbContext` into app services.

## Application services

- Interface + implementation in `Services/{Feature}/`; DTOs in `Services/Dtos/{Feature}/`.
- Use generic `IRepository<T, Guid>` unless you truly need custom queries (this template usually does not).
- Map with `ObjectMapper.Map<,>()`; add Mapperly classes in `ObjectMapping/` when new entity/DTO pairs appear.
- Expose APIs via ABP **auto API controllers** — do not add manual REST controllers for app services.
- Put `[Authorize(...)]` on mutating methods; define permissions in `Permissions/`.
- App services accept/return DTOs only, not entities.

## UI (Razor Pages)

- Pages under `Pages/{Feature}/`; page models inherit `AbpPageModel`.
- Inject `I*AppService`, not repositories.
- User-visible strings via `@L["Key"]`; add keys to `Localization/AbpTempSimpleApp/*.json`.

## Client-side libraries

After changing ABP/client packages or when `wwwroot/libs` is missing:

```bash
npm install --prefix AbpTempSimpleApp
abp install-libs --working-directory AbpTempSimpleApp
```

Do **not** install Node/npm inside `taskever.yaml` init — the sandbox template already provides Node 24.

## Build & run

```bash
dotnet restore AbpTempSimpleApp/AbpTempSimpleApp.csproj
dotnet build AbpTempSimpleApp/AbpTempSimpleApp.csproj
```

Local run uses SQLite (`ConnectionStrings:Default` in `appsettings.json`).

## Taskever preview (`taskever.yaml`)

Single **command** service (`app`) on port **8080** — see repo root `taskever.yaml`.

- Dev server binds **`http://0.0.0.0:8080`** via `ASPNETCORE_URLS` (required for E2B port routing).
- `App__SelfUrl` / `AuthServer__Authority` use `${preview.url(app)}` (browser-facing OIDC and redirects).
- `App__HealthCheckUrl` uses `${service.internalUrl(app)}/health-status` so HealthChecks UI polls loopback, not the public hostname.
- Health endpoint for the supervisor: `/health-status`.
- After C#/Razor changes, preview restarts automatically (`restartPolicy: on-change` + `watchPaths`).

## Scope & style

- Early dev repo — change DTOs, routes, and migrations cleanly; no backward-compat shims.
- Match existing naming and patterns before introducing new abstractions.
- Prefer small, focused changes; one feature at a time.
